# S-02 — no router root password on the kidsout machine

**Finding (REVIEW.1 §7, S-02).** v1's `config.example.json` told the operator to
put the router's **root** password in `config.json`. A leaked credential would
then cost the whole router, and nothing enforced the file's permissions.

## What v2 does

`router_bootstrap.sh`, run once on the router, creates a dedicated rpcd login
named `kidsout` whose ACL grants exactly:

| capability | why |
|---|---|
| `ubus session login/access` | to authenticate at all |
| `ubus uci get/set/add/delete/commit/apply/confirm/revert` on **`firewall` only** | to toggle `kidsout_xbox_out` |
| `ubus file exec` on **`/usr/libexec/kidsout-xbox` only** | counters, conntrack flush, neighbour table |
| `ubus system board` | version reporting in `status` |

`config.json` holds that password, never root's, and `xbox.py` chmods the file to
`600` on every run if it finds it group- or world-readable.

## Why a helper script instead of `file exec` on nft/conntrack

REVIEW.1 proposed scoping the ACL to "`file exec` on the specific conntrack/nft
commands". That does not actually achieve the goal:

- rpcd authorises the **command path**, not its arguments, and runs it **as
  root**.
- `file exec` on `/usr/sbin/nft` therefore permits `nft flush ruleset`,
  `nft add rule ... accept`, or any other complete rewrite of the firewall.
- A credential that can rewrite the firewall of the household router is
  root-equivalent for every purpose that matters here, so S-02 would be fixed on
  paper only.

v2 installs `/usr/libexec/kidsout-xbox`, which accepts a closed set of verbs
(`info`, `counters`, `counters-install`, `counters-remove`, `flush`, `neigh`,
`leases`, `conntrack-dump`) and validates its arguments — MACs must look like
MACs, addresses may contain only hex digits, dots and colons, so nothing can be
passed that resembles an option or a path. rpcd invokes it with an argv array and
no shell, so there is no quoting surface either.

Worst case with the `kidsout` credential in hand: an attacker can block or unblock
the Xbox, read its byte counters, drop its conntrack entries, and list the DHCP
leases and neighbour table. That is a real but bounded loss, and it is the
smallest set that still lets the driver do its job.

## Residual risk

- The helper's `leases` and `neigh` verbs disclose the LAN's device inventory.
  Acceptable: the driver needs the neighbour table for IPv6 discovery and MAC
  discovery, and this is information any device on the LAN can obtain anyway.
- `flush` can drop conntrack entries for an arbitrary address, which is a
  nuisance-level denial of service against one host on the LAN. Restricting it to
  the console's own addresses would mean hard-coding them into the helper; not
  worth the loss of flexibility for a nuisance.
- The password sits in a plaintext file readable by the account that runs
  kidsout. Moving it to a systemd credential or an environment variable is
  possible if the deployment ever justifies it.

## Related: S-03, transport security

`verify_tls: false` is still the default, because the router serves a self-signed
certificate. `./xbox.py pin` records that certificate's SHA-256 fingerprint in
`device.json`, and from then on the driver **refuses to send credentials to any
other certificate** — the check runs after the TLS handshake and before the
request body is written. That closes the LAN MITM window without needing a real
CA. Re-run `pin` if the router regenerates its certificate.

## Undoing it

```
ssh root@192.168.2.1 sh /tmp/router_bootstrap.sh --uninstall
```

removes the helper, the ACL and the `kidsout` login, and drops the nft accounting
table. It leaves every other login and every firewall rule alone.
